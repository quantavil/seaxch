# AGENTS.md — Seaxch

Personal start page for the FMHY link directory. Static only, no framework, no accounts, no tracking.

## Commands

- `bun install` — Bun >= 1.4.2
- `bun run build [--offline] [--no-nsfw] [--docs DIR] [--out DIR]` — parse pages, bundle, write `dist/`, enforce budgets
- `bun run dev [port]` — serve `dist/` (`scripts/serve.ts`, default 8080)
- `bun test` — parser, search, updater, NSFW, build, groups, pins, favicon
- `bunx tsc --noEmit` — typecheck
- `bun run docs` — download upstream pages to `.cache/docs`
- `bun run e2e` — Playwright (TypeScript, `e2e/smoke.ts`) browser suite against `dist/`: five viewports, search, section view, Back, pins, NSFW opt-in, offline, phone stability. Build first; it serves `dist/` itself. One-time browser: `bunx playwright install chromium`
- `bunx knip` — unused files/exports/dependencies; keep it clean (also run `bunx tsc --noEmit --noUnusedLocals --noUnusedParameters`)

## Architecture

- `src/shared/parse.ts` — tolerant FMHY markdown parser; invariant: every `](http` lands in one stats bucket
- `src/shared/svg.ts` — central static SVG art; no emoji anywhere in `src/`. Brand marks: DDG uses the simple-icons path and needs `fill-rule="evenodd"` (its ring + duck are separate sub-paths; without it the duck fills in and the icon renders as a solid blob). Reddit dispatches to site-wide `reddit.com/search`, not a subreddit.
- `src/build/template.ts` — SSR shell + strict CSP (`script-src 'self'` plus the two suggest hosts, styles by hash)
- `src/app/main.ts` — critical path ≤6KB gzip (prefs, shelf, Lately); `core.ts` (routing, events, boot) lazy-loads the dataset + uFuzzy + views, split into `catalog.ts` (pages, index, NSFW), `results.ts` (result list, Enter), `section-view.ts`, `settings.ts`, `dock.ts` (engine order/visibility; syncs the build-time chips), `sortable.ts` (pointer drag + keyboard on a grip), `suggest.ts` (JSONP), with shared `dom.ts` (`$`, `el`, `emit/on`, `applyTheme`) and `nav.ts` (`anchor`, `openUrl`, `bareHost`). Never import `svg.ts` or `groups.ts` from the critical path: either drags every icon / group definition into `main.js` (one `plusSvg` import took it 4.1KB → 7.7KB). The shelf's Add plus is drawn in CSS; `STARTER`/`monogram` live in `src/shared/starter.ts` (re-exported by `groups.ts`) for the same reason
- `src/app/search.ts` — uFuzzy over the full dataset. Remote suggestions are opt-in and live in `suggest.ts`
- `src/app/render.ts` — result rows: group-hue bar (CSSOM `--h`) instead of an icon, bold name + star, 1-line desc (2 in section view), muted host, extras as slim text-links. No favicons here: a row can carry several links (main, mirror, subreddit), so one icon would misrepresent it
- `src/app/plate.ts` + `src/shared/favicon.ts` — the icon plate for shelf pins and Lately only (the single-destination items): letter monogram always underneath, DuckDuckGo icon (`icons.duckduckgo.com/ip3/<host>.ico`) laid over once it loads, removed on error. Switch off in Settings → Privacy & data → Site icons (`prefs.icons`). Privacy: DDG sees the hostname of each pinned/recent site. CSP `img-src 'self' data: https://icons.duckduckgo.com` is the only third-party host, and it never appears in markup
- External search is tap-only: the dock chips in the search bar are the only dispatch surface, plus zero-hit external rows in the list. Never `addRecent` for external queries.

## Conventions

- No `innerHTML` with dataset; static SVGs only via `src/shared/svg.ts`
- Recents record main links only (extras like Subreddit/Discord are not sites)
- Search a11y: input `role=combobox` + `aria-controls/list`/`aria-expanded`/`aria-activedescendant`; list `role=listbox`; rows `role=option` + `sr-N` ids
- Light `--mut-soft` must stay ≥4.5:1 against the background
- Narrow screens (`max-width:639px`): the header is brand + gear; the search pill is docked at the bottom under the thumb (`.bar` fixed, engine chips stacked above it while there is a query, `body.q` scrim/padding), so the viewport meta uses `interactive-widget=resizes-content` to keep it above the keyboard. The placeholder is deliberately short ("Search 20,160 links"); the "Web:" label and chip names are hidden (icon-only chips, 44px). Shelf is 5 tiles per row, Lately becomes a horizontal snap row of cards, directory is 1 column of group cards. Result rows stay in the flow (not pinned above the dock)
- Home is bar-first: no hero. The search bar lives in the header (desktop: brand left, 700px pill centred, gear right; `/` focuses it). Order is the `.hub` (shelf `#pins-sec` + Lately card `#recents-sec`, single column when Lately is empty), then "Browse everything": 8 tinted group cards (`.grp`, coloured header band with the group's link total only, no folder count: the owner dislikes it) each listing its FMHY pages as rows (`.dir`: full title, count pill, `N picks` + 3 starred names from `topStarred`/`picks` in `build.ts`). Cards keep `GROUPS` order (the owner twice rejected an ascending-by-folder-count order) and sit in CSS columns (`.dirs{column-count}`, `.grp{break-inside:avoid}`) so heights balance and no card leaves a gap under it (a grid with `align-items:start` did): 4 columns, ≤1099px 2, ≤639px 1; reading order runs down each column. The dock's web chips show only while there is a query (`body.q`); home blocks hide while there is a query. No "Start from a need" pills (the owner found them useless)
- Intent layer lives in `src/shared/groups.ts`: `GROUPS` maps FMHY's 23 pages into 8 groups (every page key in exactly one, guarded by `test/groups.test.ts`), `STARTER` (re-exported from `starter.ts`) is 8 real starred links shown as non-stored tiles until the first pin. Group hue paints the directory card, its band, the result-row bar, the section header and fallback monogram tiles. Hue is applied through `[data-g="0"]…[data-g="7"]{--h:…}` slots in `style.css` (checked against `GROUPS` by a test) because the CSP blocks inline `style=""`, so never emit `style="--h:…"` from the template (CSSOM `style.setProperty` at runtime is fine). Group glyphs (`groupSvg`) appear on the section header only
- Shelf: pins keep insertion order (never click-ranked: tiles must not move under the thumb); `Alt+1..9` opens the nth shelf tile (bare digits would collide with typing) (no on-tile numbering: the owner dislikes it); the shelf is a compact left-aligned flow (fixed-width tiles), never stretched over the full width; the edit-mode remove `×` sits on the plate's top-right corner; a dashed "Add" tile (after the user's pins, not the starter set) hands focus to the search box; "Lately" shows the 6 most recent main links as `name` + `host · time ago`
- Section view has a `Picks | Everything` toggle (`picksMode` in `core.ts`, picks by default when the page has stars). Results select nothing by default: **Enter searches the first enabled web engine** (Google by default) with what was typed, never recorded in Lately; ArrowDown then Enter opens a hit or suggestion. There is no "Top hit" row or Enter hint
- Look is "Launchpad": calm, not loud. Warm paper (light, `#f4ede1`) or dark roast (dark, `#181411`) on a 28px dot grid; rounded cards with hairline borders and soft shadows; one terracotta accent (`--accent`) for focus, active chips and primary buttons; stars use `--star`. Icons sit on a neutral light `.plate` so any favicon reads in both themes. Each intent group owns one hue, applied through `hsl(var(--h) var(--gbs) var(--gbl))` style tint variables defined per theme (`--gb*` band, `--gt*` card, `--gl*` border, `--gd*` row rules, `--gp*` count pill). Body type is an explicit rounded stack (not `system-ui`: on a Linux desktop it can resolve to the user's monospace UI font). Motion is only a small lift/press transform on plates, off under `prefers-reduced-motion`. Brand mark is a squircle lens with a dot (`markSvg` in `svg.ts`, same geometry drawn by `icons.ts` for the PNG icons and `FAVICON_SVG`); the four-point star is only the FMHY-pick marker (`starSvg`). Do not use a sparkle/star as the logo (reads as generic AI branding). Theme is `prefers-color-scheme` plus `[data-theme=light|dark]` set by `applyTheme`
- Web engines: `ENGINES` in `src/shared/engines.ts` is the single source of truth (build-time dock chips, Enter, settings list, suggest providers via `sg`); stored prefs are filtered against it so removed engines can't linger. Google is first; `parsePrefs` migrates the old untouched Yandex-first order once. `syncDock` only reorders/hides the build-time chips. Suggestions: Google and Yandex via JSONP (their hosts are in CSP `script-src`, a permanent loosening even while the feature is off; the setting defaults to off and says that the typed text goes to that engine). DuckDuckGo sends no CORS headers and ignores `callback`, so it is impossible from a static page
- Count formatting lives in `src/shared/pages.ts` (`fmtCount`) because both the SSR template and the runtime render it; group hue is in `src/shared/groups.ts`. Counts must stay `en-US`: a bare `toLocaleString()` follows the reader's locale, so the same number is printed "1,234" by the server and "1 234" by the client
- Coarse pointers: 44px targets via the `@media(pointer:coarse)` block; extras reveal is gated on `(hover:hover) and (pointer:fine)`
- `main` must use `overflow-x:clip`, never `hidden`. `hidden` forces the y axis to `auto`, which turns `main` into a scroll container and silently kills every `position:sticky` inside it — the section jump strip and the section headers both stopped sticking (measured: strip at `top:-2266px` after 2,500px of scroll). `clip` clips without creating a scroll container
- Section view fold: sections longer than `COLLAPSE_N` (12) rows fold the rest away (`syncSec` in `core.ts`). `#privacy` went 39,904px → 8,380px on mobile and 37,628px → 5,445px on desktop. Rules that keep it honest: the badge shows what is visible (12, not 55) and `Show all 55` is a real `<button>` with `aria-expanded`, a plain full-width text button at the END of the card (not in the header: the owner asked), whose Show less scrolls the card back into view; expansion is remembered per visit in `expandedSecs`; a filter sets `forced` so no hit can hide behind the fold, and `filterCat` must then leave `countEl` alone or it overwrites the folded badge with the section total; the fold walks **all** `<li>` (rows *and* `.sub`) and drops a sub-header as soon as the cut is reached (`seen >= COLLAPSE_N`), otherwise `DNS FILTERS` survives with nothing under it
- Desktop ≥900px: `.cat-sec>.list` becomes a card grid (2 columns at 1180px, 12 rows/screen instead of 7) and `.x .c` drops its chip chrome for inline underlined links — a hover-revealed chip row grows the card on hover and shoves the whole grid down. `.cat-sec` needs `scroll-margin-top` (`3.5rem` below 1024px for the sticky strip, `.5rem` above) or chip/rail jumps land under the sticky header. Scroll the jump strip with `secChips.scrollTo`, never `scrollIntoView` — that scrolls the page too
- `.host` (destination, shortened to the last two labels) uses `--mut`, not `--mut-soft` at reduced opacity: that combination is 2.7:1 on the row background. Touch devices get no tooltip and no browser status bubble, so this is the only place the destination is visible
- Budgets enforced by build: html+main.js ≤20KB gzip, main.js ≤6KB gzip; no third-party hosts in html markup (only the favicon host, inside the CSP)
- Hosting: Cloudflare Pages static (`dist/_headers` immutable hashed files). No server code.

- Settings is one calm 42rem column of grouped rows (`.settings-card h3` caption + `.rows` card with hairline dividers): Search engines (drag handle with arrow-key support, switch; no up/down buttons), While you type (suggestion provider), Appearance & behaviour, Privacy & data. No multi-column card grid and no accent hero.
- Back/Home: one persistent `#hdr-back` button, icon only (no text, no border or fill, 75% opacity), on the left of the header right after the brand inside `.lead`, shown only in section view and settings. Owner asked for it minimal and unobtrusive; do not add a label or a pill, and do not move it to the right (it looked odd next to the gear). The in-page back buttons were removed. `route()` remembers the home scroll position (`homeY`) and restores it when home comes back, so leaving a section and returning does not jump to the top
- NSFW: opt-in, but never invisible. When the build ships it, the "Odds & ends" group (`k: "more"`) always lists an "NSFW" row (`#t-nsfw`, class `off`, pill "Off", "Tap to turn on", no site names leaked). One tap on it turns NSFW on, loads the file and opens `#nsfw`; the switch in Settings → Appearance & behaviour turns it off again (the `#nsfw` chip in `.opts` stays hidden as the state holder). `syncNsfwTile` flips the `off` class and the group header link total (`small[data-n]`); a failed load shows a toast and reverts the pref
- Search index (`ix`) is built lazily by `getIx()` (first query, or idle time after boot), not in `boot()`; `rebuild()` just invalidates it. `urlKeys` in `links.ts` parses each URL once for both the canonical key and host
- `.list` clips its children (`overflow:hidden`), so the first/last `.r` carry the card radius, otherwise the selected row's 3px ring is cut square at the corners
- No keyboard-shortcuts button, dialog or `?` handler: the owner knows the keys (do not re-add a "Keys" button to the footer). The keys themselves (`/`, `Ctrl/Cmd+K`, arrows, Enter, Esc, `Alt+1..9`) stay
- The service worker is cache-first for navigations, so a new build only shows after the worker swaps; `main.ts` reloads once on `controllerchange` (only when a worker already controlled the page) so one refresh is enough instead of two. The IndexedDB name `fmhy-home` in `kv.ts` is data, not branding: leave it or users lose their cached dataset

- Search result rows show no breadcrumb path and no "+N more places" (redundant while searching), the host is desktop-only (`.r .host` hidden ≤639px), descriptions are never clamped, and link chips keep a 44px hit area through a `.c::after` overlay instead of 44px of visible height. The section header has no copy-link button (the owner dropped it; `?sec=sec-N` deep links still scroll).
